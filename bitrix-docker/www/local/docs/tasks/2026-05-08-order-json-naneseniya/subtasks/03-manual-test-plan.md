# Subtask: manual test plan (`json_naneseniya`)

Связано с задачей: `local/docs/tasks/2026-05-08-order-json-naneseniya/README.md`

## Статус

**todo**

## Цель

Дать воспроизводимый ручной тест-план проверки, что `json_naneseniya` сохраняется корректно и соответствует корзине.

## Предусловия

- Есть 2 товара:
  - **Товар A**: в корзине задано `NANESENIE` с двумя значениями (например: `[{name:"Логотип",price:100.5}, {name:"Текст",price:0}]`).
  - **Товар B**: `NANESENIE` не задано или пустое.
- (Опционально) Есть кейс с двумя строками корзины с одинаковым `PRODUCT_ID` (например, два добавления одного и того же товара).

## Шаги

### 1) Smoke: оформление заказа (AJAX)

- Открыть страницу оформления заказа.
- Заполнить обязательные поля формы.
- Оформить заказ.
- Убедиться, что редирект на success происходит.

### 2) Проверка значения в админке заказа

- Открыть заказ в административной части.
- Найти свойство заказа `json_naneseniya`.
- Проверить:
  - значение — валидный JSON;
  - присутствуют объекты по товарам (по `PRODUCT_ID`);
  - у товара A `NANESENIE` содержит оба значения без пустых элементов;
  - у товара B `NANESENIE` — пустой массив.

### 3) Кейс агрегации по `PRODUCT_ID`

- Добавить в корзину один и тот же товар (одинаковый `PRODUCT_ID`) два раза (две строки).
- В первой строке указать `NANESENIE=[{name:"A",price:10}]`, во второй — `NANESENIE=[{name:"B",price:20},{name:"A",price:10}]`.
- Оформить заказ.
- Проверить, что в `json_naneseniya` только **одна** запись для этого `PRODUCT_ID`, и `NANESENIE` содержит `{name:"A",...}` и `{name:"B",...}` без дублей (дедуп по `name`).

## Ожидаемые результаты

- `json_naneseniya` не зависит от пользовательского ввода и всегда соответствует корзине.
- Пустые значения корректно нормализованы.
- Нет `pre()/die()` в процессе оформления.
