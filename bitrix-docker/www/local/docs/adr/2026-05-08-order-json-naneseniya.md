# ADR: JSON «нанесения» из корзины → order property `json_naneseniya`

## Статус

Принято (2026-05-08). Требуется реализация в компоненте: `local/components/online-service/order.form/class.php`.

## Контекст

При оформлении заказа нужно передавать в заказ агрегированную информацию по нанесениям для каждого товара. Источник данных — **кастомное свойство корзины** `NANESENIE` (множественное) у каждого basket item.

Свойство заказа (order property) с кодом `json_naneseniya` должно содержать JSON, сформированный из текущей корзины.

Важно:

- Интеграционные вебхуки/потоки n8n не меняем.
- Меняем только бизнес-логику компонента оформления заказа.

## Решение

### 1) Где формировать JSON

JSON формируется **на сервере в момент создания заказа**, в компоненте `OrderFormComponent`, непосредственно перед установкой order properties, чтобы:

- значение всегда отражало **фактическую** корзину, привязанную к создаваемому заказу;
- не зависеть от поля формы, приходящего из браузера;
- избежать невалидных/подменённых данных в `json_naneseniya`.

### 2) Формат данных

В order property `json_naneseniya` записывается JSON-объект следующей формы:

```json
{
  "id": "order-xml-id",
  "items": [
    { "id": "product-xml-id", "NANESENIE": [{"id":"enum-xml-id","name":"A","price":100.5}, {"id":"enum-xml-id-2","name":"B","price":0}] }
  ]
}
```

Где:

- `id` (корневой) — `XML_ID` заказа (`b_sale_order.XML_ID`); если пуст, генерируется UUID при сохранении.
- `items` — массив товаров с нанесениями.
- `items[].id` — `XML_ID` товара (для SKU — родительский товар).
- `items[].NANESENIE` — массив объектов `{id, name, price}`.
  - `id` — `XML_ID` enum-значения свойства инфоблока `VIDY_NANESENIY_KLASSIFIKATOR` (если известно).

### 3) Агрегация одинаковых `PRODUCT_ID`

Если в корзине присутствует несколько строк с одинаковым `PRODUCT_ID`, результирующая запись в JSON **одна**:

- значения `NANESENIE` объединяются (merge) по всем строкам этого `PRODUCT_ID`;
- затем выполняется дедупликация значений (unique).

Причина: целевая аналитика/обработка опирается на товар (`PRODUCT_ID`), а не на конкретную строку корзины.

### 4) Нормализация множественных значений `NANESENIE`

Нормализация значений `NANESENIE` перед записью:

- привести к массиву (если пришло одним объектом — обернуть в массив объектов; если пришло строкой — интерпретировать как `name` с `price=0`);
- для каждого элемента: `name` привести к строке, `trim`, отфильтровать пустые;
- `price` привести к float;
- дедупликация по `id` (если есть), иначе по `name` (ключ уникальности);
- правило коллизий по `name`: **последнее значение цены побеждает**, при этом **порядок элементов сохраняется по первому появлению** `name` в корзине (стабильный порядок).
- примечание: если значение `NANESENIE` по ошибке сохранено как JSON-скаляр строка (например `"Логотип"`), это считается некорректным входом; корректный вариант — обычная строка без JSON-кавычек или JSON-структуры `[{name,price}, ...]` / `{name,price}`.

### 5) Пустые значения

- Если у товара нет значений `NANESENIE`, в объекте указывать `"NANESENIE": []`.
- Если у всех товаров пусто, `json_naneseniya` всё равно должен быть валидным JSON: `{"id":"<order-xml-id>","items":[]}`.

### 6) Кодирование JSON

Сериализация: `json_encode(..., JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES)` (без дополнительного pretty print) и запись результата строкой в order property.

## Последствия

- Данные `json_naneseniya` становятся воспроизводимыми, серверными и непротиворечивыми корзине.
- Появляется явный контракт формата JSON, пригодный для последующего использования (в админке заказа/интеграциях).
- Риск: если в корзине `NANESENIE` хранится в разных форматах (строка/объект/JSON-строка), потребуется поддерживать безопасную нормализацию на сервере.
