# S1: Reproduce steps + evidence

- Главная задача: `docs/tasks/2026-05-01-registration-crm-unique-contact-stopper/README.md`
- Статус: `done`

## Цель

Надёжно воспроизвести обрыв registration pipeline после `registration_webhook_unique_url` и собрать артефакты, позволяющие однозначно локализовать место остановки (PHP halt vs n8n/CRM).

## Входы

- Конфиг с заполненным `registration_webhook_unique_url` (aka `/registration/crm-check-unique-contact-v1`).
- Доступ к логам n8n и логам сайта (php/log, async metrics при наличии).

## Выходы

- Шаги воспроизведения (deterministic).
- Снимок “ожидалось/получилось”: какие webhooks/шаги должны идти после unique-contact, и какие фактически не происходят.
- Минимальный набор корреляционных данных (site user id / registration uuid / idempotency key, если доступно).

## Итог / evidence summary

- Подтверждено: unique-contact pre-check (`/registration/crm-check-unique-contact-v1`) отрабатывал успешно, после чего выполнение цепочки регистрации прекращалось на стороне PHP.
- Локализация: остановка происходила в `RegisterUserCompany::crmAddContact()` из‑за безусловного `pre()/die()` (см. ADR).

## Reproduce steps (черновик)

1. Запустить регистрацию (юзкейс, где после pre-check вызывается CRM-ветка с `crmAddContact()`).
2. Подтвердить в n8n, что `/registration/crm-check-unique-contact-v1` отработал успешно.
3. Проверить, что **после** этого:
   - не выполняются ожидаемые downstream вызовы/шаги (по n8n логам и/или логам сайта),
   - отсутствуют признаки штатного завершения регистрационного сценария.

## Индивидуальные критерии готовности

1. Воспроизведение повторяемо (минимум 2 раза с одинаковым симптомом).
2. Есть артефакты, подтверждающие “успех unique-contact + отсутствие downstream”.
3. Указан участок кода/шаг, на котором выполнение прекращается (уровень метода/ветки, без спорных трактовок).
